# Nitrogen — контекст и правила работы ИИ

## Назначение
Этот файл — стартовый контекст для новых чатов о разработке Nitrogen. Перед предложением изменений ИИ должен прочитать актуальный код и соблюдать ограничения ниже. Если информация в этом файле расходится с текущим репозиторием или словами разработчика, приоритет имеют актуальный код и прямые указания разработчика.

## Проект
- Репозиторий нового проекта: `Bodden007/Nitrogen`, ветка `main`.
- Источник для переноса: `Bodden007/Nitrogen.Legacy`, ветка `master`.
- Nitrogen — кроссплатформенный HMI для промышленной азотной установки.
- Технологии нового проекта: C#, .NET 10, Avalonia 12, ReactiveUI.
- Целевые платформы: Desktop, Android, Browser; потенциально iOS.
- В дальнейшем телеметрия должна поступать через CoreLink. Пока в главном экране используются демонстрационные значения.
- Сохранять совместимость с кроссплатформенным UI, учитывать будущие trimming/AOT. Не привязывать общий UI к Windows без отдельного согласования.

## Обязательные правила взаимодействия
1. **Никаких изменений без одобрения разработчика.** Сначала анализ, затем конкретное предложение с обоснованием, затем подтверждение, и только после него код. Согласие на один шаг не означает согласия на соседние изменения.
2. **Перенос из Legacy с минимальными изменениями.** Сохранять XAML, визуальную структуру, стили, имена элементов, привязки, обработчики и поведение. Не «улучшать» работающую логику по собственной инициативе.
3. **Перед переносом сравнивать исходный файл Legacy с актуальным файлом Nitrogen.** Не делать предположений о содержимом. Если локальные правки ещё не отправлены на GitHub, запрашивать актуальный файл у разработчика.
4. **Работать пошагово: один файл или одна заранее согласованная небольшая правка за раз.** Не выдавать пачку несогласованных изменений.
5. **Код показывать прямо в чате.** Не создавать архивы или файлы с кодом, если разработчик отдельно этого не просил.
6. **Не добавлять архитектуру по собственной инициативе:** новые сервисы, интерфейсы, DI, фабрики, навигационные механизмы, библиотеки, фоновые процессы и рефакторинг — только после согласования.
7. **Не удалять функциональность молча.** Если зависимость ещё не перенесена, сохранять место вызова и ставить конкретный `TODO`, объясняя ограничение. Не подменять привязки статическими надписями без разрешения.
8. **Отделять факты от гипотез.** Не утверждать причину ошибки без проверки. Не предлагать каскад исправлений вместо сравнения с Legacy.
9. **Сохранять ранее согласованные решения.** Не возвращаться к уже отклонённым предложениям без новой причины.
10. Общение — на русском, технически и по существу. Код — C# с учётом текущего проекта.

## Как начинать следующий чат
1. Уточнить, какой **один** экран/файл/дефект рассматриваем.
2. Прочитать соответствующий файл Legacy и актуальную версию нового Nitrogen.
3. Показать точные различия и минимальный план; дождаться одобрения.
4. После одобрения выдать только согласованное изменение.
5. Попросить результат сборки/проверки, не заявляя об успехе без подтверждения.

**Главный принцип: переносить и сохранять, а не перепроектировать. Архитектурные решения принимает разработчик.**
