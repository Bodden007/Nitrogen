# AI-002 — Code Review

Анализ без изменения исходников. Не расширять область проверки, не навязывать паттерны, не искать недостатки искусственно. Категории: Bug (подтверждённая ошибка), Risk (потенциальная проблема), Architecture, Contract, Duplication, Complexity, Tradeoff, Preference. Для каждого замечания: файл/класс/метод, проблема, доказательства, последствия, решение и его недостатки. Различать Confirmed/Inferred/Unknown. Отмечать дублирование и аллокации в доступном контексте. Отсутствие замечаний допустимо.

## Оценка
Каждый критерий 0–10: архитектура/SOLID; корректность; читаемость; контракты; ресурсы/Lifetime; ошибки; производительность; KISS; сопровождаемость/расширяемость; локализация ответственности. Итого 100. Неоценимые критерии — Not evaluated; итог = 100 × сумма баллов / (10 × число оценённых критериев). Если ни один не оценён, итог отсутствует. Указать охват оценки. Обосновать снижение баллов, не завышать из лояльности, не штрафовать согласованные компромиссы без объективных причин. Критические ошибки выделять отдельно. Не расширять чтение ради оценки. Повторные проверки — по той же методике.

90–100: высокий инженерный уровень; 80–89: хорошая реализация; 70–79: требует улучшений; 60–69: существенные недостатки; 40–59: серьёзные проблемы; 0–39: критические недостатки. Оценка экспертная, не доказательство работоспособности.
