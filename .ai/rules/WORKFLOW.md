# Рабочий процесс

## AI-001 — Достоверность
Confirmed — подтверждено исходниками, документацией или разработчиком (указывать источник); Inferred — вывод; Unknown — недостаточно сведений. Не выдумывать существующие API и поведение. Запрашивать конкретный файл/контракт, не проектировать замену из-за отсутствия контекста. Противоречия сообщать разработчику. Расширение чтения репозитория обосновывать.

## AI-004 — Полномочия и режимы
Development — реализация согласованной задачи; Refactoring — сохранение поведения; Code Review — анализ без изменения кода. Не смешивать режимы без разрешения. Сначала уточнить входные требования, затем предложить решение и дождаться разрешения на реализацию. Локальный выбор цикла, имени переменной, стандартного алгоритма и приватного метода допустим в утверждённых границах. Вспомогательные классы, публичные API и инженерные/архитектурные решения согласовывать. Обязательно аргументированно возражать при инженерной ошибке; после подтверждения решения соблюдать его. Не редактировать репозиторий без разрешения; commit/push отдельно согласовывать.

## TEST-001 — Тестирование
Не обязательно для всех модулей. Написание и запуск тестов только по прямому запросу. Фреймворк, проекты, Mock/Stub/Fake, покрытие и интеграционные тесты согласовывать. Не менять архитектуру ради тестов без разрешения. Можно предложить сценарии и предупредить о рисках. Сборка не равна тестированию.

## CTRL-001 — «Делаем в лоб»
Только для текущей задачи: прямое решение, минимум или отсутствие дополнительных проверок, доверие входным данным и инвариантам, без гипотетической защиты, лишних абстракций, обёрток, помощников и будущих функций. Сохраняются публичные контракты, запрет выхода исключений за границы, обязательная безопасность оборудования и контроль аллокаций. Существенные риски сообщать; не усложнять самостоятельно.

## AI-003 — Definition of Done
Весь согласованный объём реализован; архитектура и контракты соблюдены; новый долг не создан без согласования; аллокации проанализированы; комментарии и графы актуальны; сборка проверена при доступной среде; тесты только по запросу. Не объявлять неполную задачу завершённой. Отчёт: реализованное, изменённые файлы, риски, фактически выполненные и невыполненные проверки. Не утверждать работоспособность без проверки.

## AI-005 — Наследование решений
Утверждённые решения действуют до явного пересмотра. Не открывать их заново без новых обстоятельств. Общие правила — AGENTS.md и связанные rules; проектные решения — docs/ARCHITECTURE.md; локальные — MODULE.md. Не менять правила самовольно. Противоречия согласовывать. Документация должна позволять новому агенту продолжать работу без истории чатов. Отдельная ADR-система пока не требуется.
