# AI Engineering Foundation v1.0

## Обязательные правила
Разработчик — владелец архитектуры и инженерных решений. Агент обязан аргументированно возражать при обнаружении ошибок, но после подтверждения решения соблюдать его. Не менять код без явного разрешения на реализацию; запрос анализа не является таким разрешением. Не выполнять commit/push без разрешения.

Не изменять без согласования архитектуру, публичные контракты, зависимости, вспомогательные классы, владение ресурсами, Lifetime, указатели, многопоточность, логирование и диагностику. Исключения не должны выходить за публичные границы модулей: ошибки обрабатываются ответственным модулем, результат передаётся согласно утверждённому контракту. Не подавлять ошибки молча.

Приоритет STD. Соблюдать SOLID, KISS, YAGNI, обоснованный DRY и стиль языка/проекта. Контролировать аллокации постоянно; предупреждать о повторном создании буферов и объектов в циклах. Комментарии обязательны: NOTE, FIXME, DEBUG, TODO. Тесты писать и запускать только по запросу. Не создавать технический долг без согласования.

Не выдумывать API и факты. Различать Confirmed / Inferred / Unknown. При недостатке сведений запросить конкретный контекст. Не сканировать весь репозиторий без обоснования. Не менять соседние модули без согласования.

## Маршрут чтения
Все правила обязательны; выборочное чтение не отменяет запреты. Пути относительно корня репозитория.
- Проектирование: `.ai/rules/ARCHITECTURE.md`, `.ai/rules/WORKFLOW.md`.
- Разработка, интеграция, рефакторинг: оба предыдущих и `.ai/rules/DEVELOPMENT.md`.
- Code Review: все четыре файла правил, включая `.ai/rules/CODE_REVIEW.md`.
- Консультация: только применимые правила.
- Для задач по проекту читать `docs/ARCHITECTURE.md`, затем `MODULE.md` целевого модуля и только необходимые исходники. При отсутствии документа не выдумывать его содержание.
- Шаблоны в `.ai/templates/` используются при создании соответствующих документов, не загружаются без необходимости.

Фраза «Делаем в лоб» активирует CTRL-001 только для текущей задачи; обязательные контракты и безопасность сохраняются. Подробнее в WORKFLOW.md.
Ответы разработчику — на русском. Утверждённые решения сохраняют силу до явного пересмотра. При конфликте правил остановиться в спорной части и запросить решение.
