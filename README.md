# Nitrogen

Кроссплатформенное приложение HMI для проекта Nitrogen.

**Репозиторий:** https://github.com/Bodden007/Nitrogen  
**Предыдущая реализация (источник для переноса экранов):** https://github.com/Bodden007/Nitrogen.Legacy

> Этот README одновременно служит стартовым контекстом для новых чатов с ИИ. Описание текущего состояния ниже относится к этапу миграции на 28.10.2026. Перед изменениями проверяй фактическое состояние репозитория: код имеет приоритет над этим описанием.

## 1. Текущая задача

Перенести **представления (Views)** из `Nitrogen.Legacy` в новый `Nitrogen` с сохранением кроссплатформенной архитектуры. Не переносить автоматически старую бизнес-логику, Modbus-обмен, сервисы и инфраструктуру: их перенос или переработка согласовываются отдельно.

## 2. Технологии и платформы

- C# / .NET 10.
- Avalonia UI, XAML (`.axaml`).
- ReactiveUI для ViewModel (`ReactiveObject`).
- Проекты решения: `Nitrogen`, `Nitrogen.Desktop`, `Nitrogen.Android`, `Nitrogen.Browser`.
- Проект `Nitrogen.iOS` присутствовал в решении, но на текущем этапе его запись закомментирована из-за отсутствующего iOS workload. Не удалять его без согласования.
- Цель архитектуры — совместимость с trimming / AOT, где это поддерживается платформой. Успешный обычный `dotnet build` **не является** подтверждением AOT-совместимости.

## 3. Согласованные решения

1. Общая UI-разметка размещается в `Nitrogen/Views/MainView/MainView.axaml`; `MainView` — `UserControl`.
2. Desktop-оболочка — `Nitrogen/Views/MainWindow/MainWindow.axaml`; `MainWindow` — `Window`, содержащий `MainView`.
3. `MainViewModel` располагается рядом с `MainView`: `Nitrogen/Views/MainView/MainViewModel.cs`.
4. `MainViewModel` наследуется от `ReactiveObject`, а не от шаблонного `ViewModelBase`.
5. Шаблонные `ViewLocator.cs` и `ViewModels/ViewModelBase.cs` удалены. Глобальная регистрация `ViewLocator` в `App.axaml` удалена.
6. Не использовать рефлексию для поиска и создания View: никаких `Type.GetType()`, `Activator.CreateInstance()` и соглашений об именовании, требующих динамического поиска типов. Будущая навигация — через явные типизированные фабрики/сопоставления, после отдельного обсуждения.
7. `ReactiveUI` и `Avalonia.ReactiveUI` — разные пакеты. На данном этапе для ViewModel выбран базовый `ReactiveUI`; интеграционный пакет не добавлять без обоснованной необходимости.
8. Общие компоненты и логика должны оставаться пригодными для Desktop, Android и Browser. Не вносить Desktop-only зависимости в общий UI.

## 4. Ориентировочная структура

```text
Nitrogen.slnx
Nitrogen/
  App.axaml
  App.axaml.cs
  Views/
    MainView/
      MainView.axaml
      MainView.axaml.cs
      MainViewModel.cs
    MainWindow/
      MainWindow.axaml
      MainWindow.axaml.cs
Nitrogen.Desktop/
Nitrogen.Android/
Nitrogen.Browser/
Nitrogen.iOS/        # пока исключён из сборки решения
```

Это **не** исчерпывающее дерево репозитория. Новые каталоги, слои, интерфейсы и сервисы не создавать только ради «красивой архитектуры».

## 5. Состояние на 28.10.2026

После реорганизации `MainView` / `MainWindow`, перехода `MainViewModel` на ReactiveUI и удаления шаблонных `ViewLocator` / `ViewModelBase` команда:

```powershell
dotnet build .\Nitrogen.slnx
```

успешно собрала `Nitrogen`, `Nitrogen.Desktop`, `Nitrogen.Android` и `Nitrogen.Browser`.

Остаётся одно предупреждение Browser/WebAssembly: нативные ссылки SkiaSharp/HarfBuzzSharp не линкуются при отключённых `WasmBuildNative` и `RunAOTCompilation`. На данном этапе оно **не является ошибкой компиляции**. Фактическую работу UI на каждой платформе и AOT нужно проверять отдельно.

## 6. Правила работы с ИИ

**Приоритет:** надёжность изменений, сохранение работающего кода, контроль разработчика.

1. **Один шаг за раз.** Сначала предложи одно конкретное изменение, затем дождись результата или подтверждения. Не выдавай длинную цепочку несогласованных правок.
2. **Не угадывай содержимое файлов.** Если код не предоставлен, запроси конкретный файл или изучи актуальную версию в репозитории. Не считай этот README доказательством текущего состояния кода.
3. **Ничего не удаляй самовольно.** Перед удалением файла, класса, зависимости, регистрации или папки проверь все использования и объясни последствия для каждой платформы.
4. **Не меняй архитектуру без согласования.** Не добавляй слои, сервисы, базовые классы, интерфейсы, контейнеры DI, пакеты NuGet и новые каталоги без конкретной задачи.
5. **Не переписывай рабочий код без причины.** Минимальный дифф; не трогай соседние файлы, форматирование и имена, если это не требуется.
6. **AOT/trimming — архитектурное ограничение.** Не предлагай рефлексию, динамический поиск типов или runtime-генерацию кода как решение по умолчанию. Не утверждай, что код AOT-совместим, пока это не проверено соответствующей сборкой/публикацией.
7. **Разделяй платформы.** Общие View и ViewModel не должны зависеть от Desktop API; учитывай Android и Browser.
8. **Различай факт, предположение и предложение.** Не выдавай будущие архитектурные идеи за уже реализованные компоненты.
9. **При ошибке сборки** разбирай конкретное сообщение компилятора и предлагай минимальное исправление. Не делай несколько независимых изменений одновременно.
10. **Не переноси Legacy целиком.** Используй его как источник для согласованного переноса представлений, а не как разрешение копировать всю архитектуру.
11. **Формат ответа:** русский язык, технически точно, кратко, без вводных лекций. PowerShell-команды должны работать из корня `C:\Dev\Csh\job\Nitrogen`. Если нужен код — указывай точный путь файла и показывай только согласованное изменение.
12. **Контроль у разработчика.** ИИ предлагает и объясняет; пользователь принимает архитектурные решения и проверяет результат.

## 7. Проверка после каждого изменения

Из корня репозитория:

```powershell
dotnet build .\Nitrogen.slnx
```

Для более компактного вывода ошибок:

```powershell
dotnet build .\Nitrogen.slnx --verbosity quiet -clp:ErrorsOnly
```

Не путать отсутствие ошибок компиляции с успешным запуском, корректной навигацией или подтверждённой AOT-совместимостью.
