# Nitrogen

Кроссплатформенный HMI-интерфейс для азотной установки. Проект переносится с **Nitrogen.Legacy** на **Avalonia UI / .NET 10**.

**[Исходный проект (Legacy)](https://github.com/Bodden007/Nitrogen.Legacy)** · **[Текущий репозиторий](https://github.com/Bodden007/Nitrogen)**

## Технологии

- C# / .NET 10, Avalonia UI (AXAML), ReactiveUI.
- Платформы: Desktop, Android, Browser; iOS пока исключён из сборки решения.
- Цель: кроссплатформенный UI с учётом trimming / AOT.
- Источник будущих технологических данных — CoreLink (интеграция ещё не выполнена).

## Текущее состояние

- **Главный экран** перенесён из Legacy с сохранением разметки, стилей и привязок.
- **MainViewModel** использует демонстрационные значения; реальная телеметрия пока не подключена.
- **Меню** перенесено, открывается через `ScreenHost`; выход возвращает на главный экран.
- **Клавиатура:** Desktop `MainWindow` принимает `KeyDown`, `MainView` обрабатывает команды и передаёт их активному экрану через `IHotKeyScreen`. Проверены клавиши `1`, `2`, `3` и работа меню.
- Остальные экраны и полноценная навигация пока не перенесены; соответствующие вызовы помечены `TODO`.
- Повторное создание `MenuControl` при открытии — известный технический долг, отложен до согласованной доработки навигации.

## Структура

```text
Nitrogen.slnx
Nitrogen/             # общий UI, Views, ресурсы и стили
Nitrogen.Desktop/     # Desktop-хост
Nitrogen.Android/     # Android-хост
Nitrogen.Browser/     # WebAssembly-хост
Nitrogen.iOS/         # пока не участвует в сборке решения
```

Главный экран: `Nitrogen/Views/MainView/`. Desktop-оболочка: `Nitrogen/Views/MainWindow/`. Меню: `Nitrogen/Views/Menu/`.

## Сборка и запуск

Из корня репозитория:

```powershell
dotnet build .\Nitrogen.slnx --verbosity quiet -clp:ErrorsOnly
dotnet run --project .\Nitrogen.Desktop
```

Предупреждение Browser о нативных зависимостях SkiaSharp/HarfBuzzSharp при выключенной нативной WebAssembly-сборке не означает ошибку обычной компиляции. AOT и работу каждой платформы проверять отдельно.

## Правила разработки

- **Legacy — эталон поведения и разметки** при переносе экранов. Не удалять элементы, обработчики и привязки без согласования.
- **Минимальный diff:** один файл или одно согласованное изменение за шаг; сначала анализ исходника, затем одобрение, затем код.
- **Без самовольного рефакторинга:** не менять навигацию, управление фокусом, архитектуру, зависимости и жизненный цикл экранов без разрешения.
- Общие View не должны зависеть от Desktop API; не использовать рефлексию для автоматического поиска View.
- Проверять фактическое содержимое файлов перед правками. Код репозитория важнее описания в README.
- Не считать успешную сборку доказательством корректной работы UI или AOT.
